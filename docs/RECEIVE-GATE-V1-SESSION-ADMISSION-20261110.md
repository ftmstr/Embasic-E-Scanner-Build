## Trusted construction and finite policy

`ReceiveGateV1.open/Open` accepts only validated, caller-trusted policy:
a canonical nonzero lowercase `expectedSessionId`, SHA-256 digest of the
random one-time QR token's 64-character lowercase ASCII hex encoding,
nonnegative issue epoch, strictly later expiry with TTL at most **300,000 ms**,
strictly positive `maxPageBytes`, and `maxPages` in **1..1000**.
Malformed policies fail closed; the raw token is never retained by the guard.
Production token must be generated by a CSPRNG **outside this guard**.
No hardware identity (MAC, IMEI, Android ID), user document or secret is in the
PUBLIC fixtures.

On `authenticate/Authenticate(presentedToken, now)`, the raw token must have
exactly 64 lowercase hex characters. Its ASCII SHA-256 is checked by
constant-time binary digest equality; only one successful transition
`PENDING -> AUTHORIZED` is possible per instance. Lock/synchronized guards
serialize simultaneous attempts. Failed guesses cannot directly authorize
page transfer; rate limiting/network peer authentication are separate gates.

The trusted clock must not roll backwards against last observed time and
must satisfy `issuedAt <= now < expiresAt`; at expiry, the guard becomes
terminal `CLOSED` and clears pending staging metadata. A caller must use
its authenticated time source; untrusted JSON fields never supply a clock.
Persisted replay resistance across process/device restart, clock attestation,
revocation propagation and resumed session identity are **NOT VERIFIED**.

## Page order, identity and staging metadata

After authorization, `propose/Propose` admits only exact bounded raw
`PageWireV1` metadata bound to the trusted session ID plus a *complete*
in-memory payload whose size and SHA-256 match the envelope. It requires
the next consecutive index starting at zero, a previously unused page ID,
fewer than `maxPages` pages and no other pending proposal.
This transitions `AUTHORIZED -> STAGED`.

`confirmReread/ConfirmReread` accepts only a fresh byte array provided
by the *caller* and matching the pending envelope digest/size. On success
the page ID is reserved, next index increments, pending metadata is removed,
and the guard returns to `AUTHORIZED` for another page. A bad or truncated
reread does not silently clear the pending proposal; the caller may retry
until session expiry or explicit `close/Close`.
All mutating methods serialize their changes to avoid intra-process races.
Cancellation is terminal `CLOSED` (not retryable); there is no rollback
of prior confirmed in-memory metadata.

**Critical staging limit:** `STAGED` is only an accepted proposal and
`confirmReread` trusts the caller to supply actual re-read bytes. There is
NO staging path validation, fsync, atomic move, persistent ledger, file
permissions, file identity or crash-restart recovery here. An attacker
controlling the adapter could pass original memory bytes. Neither `STAGED`
nor successful `confirmReread` authorizes `RECEIVED`/`READY` or export.
A future trusted storage adapter MUST perform bounded streaming staging,
safe image magic/pixel decode, re-open and hash verification, atomic replace,
durable one-time token/page replay ledger and crash tests.
